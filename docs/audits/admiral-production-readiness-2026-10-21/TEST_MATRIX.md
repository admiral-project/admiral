### R73 CentOS Stream 10 Multi-Node scoped records

Three real CentOS Stream guests passed secure installation and registration. Explicit placement, same-key replay and cleanup passed on W1 and W2; a three-client same-key race converged to one operation/task/instance; real W1 and W2 reboots recovered PostgreSQL markers, HTTP 200 and healthy/available state. Active W2 removal was refused while its workload was healthy; idle removal deleted its database record and revoked the live/persistent WireGuard peer and prior Fleet token. A controlled revocation-helper failure returned HTTP 503 after four requests while preserving the active worker record, token fingerprint and live/persistent peer. Restoring the packaged helper allowed successful removal and retry; secure re-enrollment and post-re-enrollment workload placement on both workers passed. A hub reboot after removal did not restore W2's node record or peer; W1's route and fresh heartbeat returned. The tested private UI path timed out from W2. A real W2 partition made the workload unavailable immediately and the node offline/degraded after its heartbeat timeout; route restoration recovered both, SQL data and HTTP. A separate hub reboot restored services, routes, worker heartbeats and an active W1 workload with SQL and HTTP intact. The initial W1 install failure was caused by its stale COPR R57 package/repository configuration; the clean R73 retry passed, and the failure is not a product finding. The cell remains PARTIAL: broader security and consistency scenarios remain. Exact timings, run IDs, hashes and reproduction scripts are in [`release73-centos-multinode-progress.md`](evidence/release73-centos-multinode-progress.md); the earlier W2-only snapshot is retained in [`release73-centos-multinode-bootstrap.md`](evidence/release73-centos-multinode-bootstrap.md).
