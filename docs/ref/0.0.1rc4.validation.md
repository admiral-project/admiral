## Historical candidate: Admiral Fleet `0.0.1rc4-5`

The previous set used Fleet source commit `059d3503f3e1369eef5c0497f0206bee973aafba` and RPM SHA-256 `a357f00f6a7a319115fd888702db3a0e6c7ed5cd48e87aeb7693301008241204`. Its six clean installer scenarios completed, but Rocky single-node WordPress image update failed. Operation `op_6c5c3c62e30b095b` was killed after about 57 seconds while pulling `wordpress:6.8.1`; no kernel or cgroup OOM event was present. The package source had not incorporated the already tested ten-minute pull timeout from Fleet PR #87, commit `1b047c66`.

After pinning the corrected Fleet source, the new `fleet-6` RPM passed `make rpm-admiral-fleet` and its `%check`. A focused retry on the previously used Rocky VM installed Fleet `-6`, cleared the `wordpress:6.8.1` image cache, then completed restart operation `op_80875a83306f777e` in 44 seconds. HTTP returned 301, `need_restarting=false`, and the running image ID changed from `5bd67543f050fc873792b3bb092c9db43eaaa3d58f1d51dc633e0fd1fe0636d6` to `36e2490fa1a957f3cee615693157139c64b69951dcc7bfd48ee4fd6d03750a31`. This focused check is diagnostic only; final acceptance requires the clean matrix with the corrected shared set.
